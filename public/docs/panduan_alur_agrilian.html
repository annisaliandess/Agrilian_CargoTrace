Bab 1: Latar Belakang & Konteks Nyata Sistem

Halaman 2
💡 Inti Masalah yang Diselesaikan AgriLian CargoTrace:

Kopi Arabika Gayo adalah komoditas bernilai tinggi kelas dunia. Namun, Kabupaten Aceh Tengah (Takengon) berada di dataran tinggi pegunungan tanpa pelabuhan laut langsung. Untuk sampai ke pembeli di Eropa (Rotterdam), kargo harus menempuh jalur darat pegunungan yang rawan longsor, transit di Bireuen, masuk ke Pelabuhan Belawan (Medan), lalu berlayar dengan kapal kontainer samudera menyeberangi Selat Malaka. Sistem ini hadir agar setiap kilogram komoditas terpantau secara transparan, aman dari kerusakan cuaca, dan tervalidasi sertifikasinya.

1. Karakteristik Komoditas Unggulan

01. Kopi Arabika Gayo
Specialty Grade 1

Ditanam di ketinggian 1.400–1.600 mdpl. Wajib dijaga kadar airnya pada rentang 11.5% - 12% dalam kantong kedap udara GrainPro.

02. Kakao Dataran Tinggi
Fermentasi Organik AA

Biji kakao fermentasi 95% dengan kadar air 7.5% untuk bahan baku cokelat premium Eropa.

03. Minyak Nilam (Patchouli)
Minyak Atsiri Ekspor

Kadar Patchouli Alcohol > 32%, dikemas dalam drum baja bersegel pabean untuk industri parfum global.

2. Koridor Ekspor Multimoda 3 Tahap

01
Tahap 1: Koridor Darat Pegunungan (Truk Berpendingin / Reefer Truck)

Membawa kargo menuruni jalur pegunungan Takengon menuju Bireuen lalu berlanjut ke Medan (jarak ±420 km, durasi 12 - 16 jam). Truk berpendingin menjaga kelembaban agar biji kopi tidak berjamur.

02
Tahap 2: Hub Konsolidasi Ekspor (Terminal Petikemas Pelabuhan Belawan)

Kargo diperiksa oleh Karantina Pertanian (Fitosanitari) dan Bea Cukai. Kontainer dipasang segel resmi (*customs seal*) dan dicolokkan ke listrik (*reefer plug*) sebelum dimuat ke kapal.

03
Tahap 3: Koridor Pelayaran Samudera (Armada Kapal Petikemas / Ocean Liners)

Kapal kontainer berlayar menyeberangi Selat Malaka menuju pelabuhan singgah (Singapura), lalu menempuh pelayaran lintas benua selama 20–24 hari menuju Pelabuhan Rotterdam (Belanda).

Bab 2: Pembagian Peran Pengguna (RBAC) & Fitur

Halaman 3

Sistem menggunakan sistem otorisasi ketat berbasis peran (*Role-Based Access Control*). Setiap peran memiliki batasan yang jelas agar keamanan data kargo terjamin:

Peran (Role) Pengguna Contoh Wewenang Utama Batasan Sistem
Admin Sistem admin@agrilian.com
(Ayaa Liandes)		 Melihat dasbor radar global, grafik status donat, grafik tonase bar, peta sebaran GIS, audit trail semua aktivitas. Akses tak terbatas (*Super Administrator*).
Operator Lapangan operator@agrilian.com
(Dispatcher Takengon)		 Menerbitkan Manifes Baru, mencatat checkpoint perjalanan kargo, update status (Terkirim, Tertahan), lapor kendala cuaca. Hanya fokus pada operasional fisik pergerakan kargo.
Pelanggan / Buyer buyer.amsterdam@eurocoffee.nl
(Buyer Rotterdam)		 Memantau kontainer miliknya, melihat grafik pesanan, Cetak Surat Jalan Fisik (A4), Lapor Klaim / Retur Barang Rusak. TIDAK BISA buat manifes baru (403), tidak bisa intip data pesanan pelanggan lain.
Tamu (*Guest*) Pengunjung Umum Melihat Landing Page, form Cek Resi, dan Katalog Komoditas Gayo. Saat cek nomor resi, otomatis diarahkan login demi privasi kargo.
📦 Alur Pengembalian Barang & Klaim Mutu untuk Pelanggan (Customer):

Ayaa sebelumnya bertanya: "apakah pelanggan perlu buat manifes baru, atau pengembalian barang aja?"
Jawabannya: Pelanggan tidak menerbitkan manifes ekspor, melainkan mengajukan Klaim Ketidaksesuaian Mutu (*Quality Dispute / Damage Claim*). Alurnya:

  1. Pelanggan login ke akunnya → Buka Dasbor Pelanggan → Lihat tabel pengiriman aktif.
  2. Jika barang rusak atau kadar air tidak sesuai saat tiba, klik tombol "Lapor Klaim / Retur".
  3. Akan muncul Modal Pop-Up Web Resmi AgriLian. Pelanggan memilih tingkat urgensi (*LOW, MEDIUM, HIGH*) dan menuliskan detail kerusakan.
  4. Sistem mencatat laporan kendala secara otomatis, menghitung ulang estimasi, dan memberi notifikasi ke Operator untuk menerbitkan resi retur baru jika disetujui.

Bab 3: Arsitektur Rekayasa Web & Fitur Unggulan

Halaman 4
1. Pola Service Layer (Bukan Fat Controller)

Logika bisnis tidak ditumpuk di controller, melainkan dipisah ke service khusus:

  • ShipmentService: Menjaga transisi status kargo agar tidak melompat ilegal (*state machine*).
  • TrackingService: Mencatat riwayat perjalanan kargo yang tidak bisa diubah (*immutable audit trail*).
  • EtaService: Menghitung keterlambatan otomatis jika truk terhenti.
  • CurrencyService: Mengambil kurs resmi Bank Sentral Eropa (ECB) secara *live*.
2. Peta Geospasial GIS (Leaflet.js)

Mengapa menggunakan Leaflet.js ketimbang Google Maps?

  • Gratis & Bebas Lisensi: Menggunakan tiles OpenStreetMap tanpa perlu kartu kredit atau kuota tagihan Google.
  • Ringan & Cepat: Peta memuat koordinat rute Takengon → Bireuen → Belawan → Rotterdam dalam sekejap.
  • Interaktif: Marker memiliki warna status dinamis (Hijau = Normal, Kuning = Tertunda).
3. Sistem Pop-Up Toast Web Elegan

Sistem tidak menggunakan alert kuno bawaan browser (`alert()`), melainkan komponen Floating Web Toast di pojok kanan atas dengan animasi halus, ikon status, tombol tutup `(X)`, dan otomatis menghilang dalam 5 detik.

4. Surat Jalan Fisik Cetak A4

Halaman `/shipments/{id}/print` menghasilkan dokumen surat jalan resmi standar logistik internasional, lengkap dengan Barcode Code128, QR Code Lacak, tabel muatan, dan lembar tanda tangan pengesahan 3 pihak.

5. Otomatisasi Pengujian di GitHub (GitHub Actions CI)

Setiap kali kode di-push ke GitHub, sistem otomatis menjalankan 18 unit & feature tests (75 assertions) di server cloud Ubuntu PHP 8.3. Ini memastikan tidak ada error logika atau celah keamanan sebelum aplikasi dipresentasikan saat UAS.

Bab 4: Panduan Tanya-Jawab Ujian UAS (Cheat-Sheet)

Halaman 5

Berikut adalah bocoran pertanyaan yang paling sering diajukan dosen penguji Pemrograman Web dan cara menjawabnya dengan tenang, percaya diri, dan berbobot:

1. Dosen: "Mengapa sistem ini dinamakan Logistik Multimoda? Kenapa tidak pakai truk saja sampai selesai?"

Jawaban Ayaa: "Karena komoditas ini ditujukan untuk ekspor lintas benua ke Eropa (Rotterdam). Takengon berada di dataran tinggi pegunungan tengah Aceh yang tidak punya laut, sehingga tahap pertama wajib menggunakan truk berpendingin (jalur darat). Namun truk tidak bisa menyeberangi samudra, sehingga di Pelabuhan Belawan muatan dialihkan ke kapal kontainer samudera (jalur laut). Perpindahan dari moda darat ke moda laut inilah yang disebut logistik multimoda, Pak/Bu."

2. Dosen: "Bagaimana cara sistem Anda menjaga keamanan data pelanggan?"

Jawaban Ayaa: "Kami menerapkan Role-Based Access Control (RBAC). Pelanggan hanya bisa melihat manifes miliknya sendiri di database melalui query filter where('customer_id', $user->id). Jika pelanggan sengaja mengetik nomor resi pelanggan lain atau membuka URL buat manifes, sistem langsung memblokir dengan kode HTTP 403 Forbidden."

3. Dosen: "Apa keunggulan arsitektur backend yang Anda gunakan?"

Jawaban Ayaa: "Saya memisahkan logika bisnis menggunakan Service Layer Pattern (seperti ShipmentService, EtaService, dan CurrencyService). Controller hanya bertugas menerima input dan mengembalikan response, sehingga kodingan sangat rapi, mudah dirawat, dan terbukti lolos 18 skenario Automated Unit Testing dengan 75 assertions di GitHub Actions."

4. Dosen: "Bagaimana sistem memperkirakan keterlambatan kargo?"

Jawaban Ayaa: "Sistem membandingkan waktu estimasi tiba (ETA) dengan jadwal resmi. Jika terjadi bencana cuaca atau antrean di pelabuhan, operator mencatat 'Exception', dan EtaService secara otomatis mengkalkulasi ulang durasi keterlambatan ke dalam kategori LOW, MEDIUM, atau HIGH, lalu memperbarui radar peta secara otomatis."
